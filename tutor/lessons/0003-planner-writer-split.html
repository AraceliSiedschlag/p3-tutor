What the planner does 1 min

An agent splits its work into two jobs. The planner reasons about the whole task up front: it orders the sub-steps and notes which depends on which, before any output is produced (LangChain; TianPan).

Picture an IT dispatcher reading every open ticket at shift start: they set the order and flag that ticket 2 needs ticket 1's account reset first. They never touch a ticket themselves.
A common mix-up

"The planner should just write the output itself, since it knows the whole task." Tempting, but mixing the two jobs causes the myopic, error-compounding failures in the next two sections.

What the writer does 1 min

The writer (or executor) works at the step level: it turns one assigned step into output — text, a tool call, a file — using only that step's context (TianPan). This lets each role specialize, as Comet notes: the planner runs a slower, stronger reasoning pass, while the writer stays simple, even a cheaper model (LangChain).

Picture a line cook on a busy night: the ticket says "plate the salad," and that's all they need — not the dessert order three tickets down.
A common mix-up

"The writer needs the whole task's history." Tempting, since more context feels safer, but a crowded context causes mistakes to pile up ("context rot"); it only needs its own step's inputs.

Why the split pays off 1 min

The planner is consulted once up front, not before every action. A ReAct-style agent calls the model before every tool use instead, deciding and producing in one breath; the split skips that cost and runs faster and cheaper (LangChain).

Keeping planning separate also lets the system replan: after a step runs, the planner reassesses and decides whether to finish or issue a new plan (LangChain).

Picture a data-science lead who plans the whole pipeline once instead of re-approving every line a teammate writes, and can still step back in to revise the plan.
Two common mix-ups

"It's just a speed/cost trick, not about quality." Wrong: an unseparated loop also makes myopic, derailed choices, a quality problem, not only a slower one.

"Planning and writing must run in parallel." Wrong: the split is distinct steps in sequence — plan, write, maybe replan — never two systems at once.

What goes wrong without it 1 min

Without separation, a system that decides and produces in the same step tends toward "greedy" choices: whatever looks good for the next action, not the best plan for the whole task, and this derails complex tasks at a high rate (TianPan).

Mistakes also pile up in one stream of context ("error self-conditioning," "context rot"), so accuracy drops the longer an unseparated agent runs (TianPan).

Back at the help desk: an engineer grabbing whatever ticket looks easiest, ignoring the dispatcher's order, can unplug the wrong server mid-migration.

Worked example and practice 1 min

Worked example: a 3-ticket help-desk job
  1. Planner's output: order 1, 2, 3; ticket 2 needs ticket 1's reset done first. No reply yet, only order.
  2. Writer's output for ticket 1: given only "user locked out, reset the account," it resets and replies — never seeing tickets 2 or 3.
  3. Notice: the writer did not re-decide the order; that was already handed to it.
Your turn, data scientist

Same pattern, a cooking task. Planner decided: step 1 boil pasta, step 2 make sauce (needs step 1's pasta water), step 3 plate. Step 1's output, modeled: "Boil water, add pasta, cook 9 minutes, reserve 1 cup pasta water." Write step 2's output. No step 3, no re-deciding the order.

Show a solution

"Heat oil, add garlic, add the reserved pasta water and butter, simmer until it thickens." Only step 2's own inputs, no plating, no re-checking the order — that is already done.

Summary 1 min

  • The planner decides the order of steps, and their dependencies, before any output exists.
  • The writer produces output for one step at a time, using only that step's inputs.
  • Keeping the two apart beats mixing them: it avoids myopic choices and piled-up mistakes, not just saves time and money.
  • Replanning only works because planning stays a separate, revisitable step.

You already think this way at work, so this pattern should click fast.
