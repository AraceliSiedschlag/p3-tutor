Cheat sheet

Context and memory

One page back to lesson 0001, objective O3.

Core terms

  • Context — everything the model is given for one call: system instructions, tool descriptions, conversation so far, latest tool result.
  • Context window — the token limit on that one pile; shared between input and output.
  • Token — the chunk of text the model reads/writes, roughly ¾ of a word.
  • Context rot — accuracy at recalling a fact drops as the window fills with tokens, even unrelated ones.
  • Note (agentic memory) — a small fact the program writes outside the context window and reads back later.
  • Retrieval — fetching just the relevant chunk of something too big to carry, on demand, instead of pre-loading all of it.
  • Progressive disclosure — narrowing in on the right chunk through a sequence of searches, rather than one guess.

What survives what

BoundaryWhat happens by defaultHow to change it
Between steps, same sessionEverything accumulates — nothing is dropped automaticallySummarize or drop old tool results on purpose
Between sessionsWhole context window is discarded; nothing carries overWrite a note before the session ends; read it back at the start of the next one
A source too big for context (a manual, a logbook)Never loaded in fullRetrieval: search for and fetch just the relevant chunk, when needed

Notes vs. retrieval

 NotesRetrieval
Best forSmall, rarely-changing factsLarge sources, searched fresh each time
Typical failureFact was never written downSearch missed the right chunk

Misconceptions to watch for

M7 — "A bigger context window makes the agent more reliable." Wrong: more tokens in the pile, including stale ones, causes context rot, not better recall.
M3 — "The agent automatically remembers earlier conversations." Wrong: nothing crosses a session boundary unless a note was deliberately written and read back.
M8 — "If it can search the source, it has effectively read all of it." Wrong: the model only ever sees the chunk a search actually returned.
