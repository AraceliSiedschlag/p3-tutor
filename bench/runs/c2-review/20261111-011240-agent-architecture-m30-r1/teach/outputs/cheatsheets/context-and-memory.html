Context, memory and retrieval

Quick reference for Objective O3 · from lesson 1

Definitions

Context window
All the text sent into one model call — system prompt, history, tool results, tool definitions, output — measured in tokens. The model has no state outside it.
Token
A roughly word-sized chunk of text; what context windows and pricing are measured in.
Context rot
Accuracy and recall get worse as token count grows, even below the window limit. More context isn't automatically better.
Retrieval
Searching a large, mostly static reference (a manual) for just the relevant passage, and loading only that into context, on demand.
Note (structured note-taking)
A small fact written deliberately to storage, then loaded back into context later — the only thing that survives a session on purpose.

What persists, and when

BoundaryWhat carries over automatically
Within one run (step to step)Everything so far — the program resends the full accumulated history every call.
Across sessions (visit to visit)Nothing. The transcript is discarded unless the program explicitly saved something and loads it back in.

Which tool for which fact

The fact is…Use
Large, static, shared by everyone (a manual, a policy)Retrieval — search it, load only the relevant passage.
Small, specific to one person or case, must survive to next timeA note — write it on purpose, load it back in at session start.

Watch for: assuming the model "just remembers" a returning student (it never does, without an explicit save-and-reload step), and assuming more context in a prompt is free or harmless (it costs money every call, and can make answers worse via context rot).

Rule of thumb: if the fact is already written down somewhere big and unchanging, retrieve it. If it's small, specific, and needs to outlive this session, save a note for it. Never assume either happens on its own.
