Context, memory, retrieval

One page. From lesson 0001-context-window-and-memory.html (objective O3).

The three ideas, side by side

IdeaWhat it isWho manages itMakerspace example
Context windowEverything the model sees on one call: system prompt, tools, conversation so far, tool results. Measured and billed in tokens.Grows automatically within a run; never shrinks on its own.Call 3 in a run sees calls 1–2's content plus every tool result since.
Memory (notes)A fact your own program creates and wants later — written to a persistent record outside any context window, read back only when relevant.The program: writes rarely and on purpose, reads just the one record needed.check_training_record reads a database row written when a student finished training.
RetrievalReference material that already existed, too big to preload — fetched just-in-time, by tool call, instead of stuffed into every prompt.The program: keeps the full document outside context; the model asks for a slice when it needs one.search_manuals(machine, topic) returns one passage instead of the whole 40-page manual.

What survives what

BoundaryWhat carries over by default
Step → step, same runEverything so far, in full — the window only grows.
Session → sessionNothing. The model holds no notebook of its own; only what the program explicitly saved and reloads crosses this line.

Two mix-ups to catch yourself making

"A bigger context window gives it memory." It doesn't — every session still starts from an empty window, no matter how large. Memory comes from a persistent record outside any window, not from window size.
"Load everything, just in case." More tokens in context costs more every time and makes the right detail harder to find amid the irrelevant rest (context rot). Retrieve the one relevant slice instead.

One-line rule

If it's a fact your own program produced, save it as a note. If it's reference material that already existed, fetch it by retrieval. Either way: keep it out of context until a call actually needs it.
