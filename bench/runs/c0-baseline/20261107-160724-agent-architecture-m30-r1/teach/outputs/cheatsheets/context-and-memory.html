Context and memory, at a glance

Four terms

TermWhat it is
TokenThe smallest unit of text a model processes; roughly 3.5–4 characters of English.
Context windowEverything the model can see in one call: system prompt, tool definitions, conversation/tool history so far, current input, and its own output. All of it is billed; none of it persists on its own.
Context rotRecall accuracy drifts down, gradually, as token count in the window grows — not a cliff, but never a reason more context is automatically safer.
MemoryAnything saved outside the context window on purpose (a file, a database row, a note) so a later session can read it back in. Nothing crosses a session boundary unless something does this.
RetrievalSearching a large, mostly static store (manuals, docs) at question time and pulling in only the matching piece, instead of holding the whole store in context.

Deciding what goes where

  1. Context Does the model need this fact for this call only, and is it already small? Just include it — the current question, a single tool result, the last couple of turns.
  2. Retrieve Is the fact sitting in a large, mostly unchanging document (a manual, a policy, past tickets)? Don't paste the document — add a search tool and pull in only the matching chunk, on demand.
  3. Save as memory Does the fact need to survive past this session, or describe state about a person/thing that no document contains (a student's training date, a machine's known quirk)? Write it to a file or database when it becomes true, and read it back in at the start of later sessions.

Two mix-ups to catch yourself making

M3 — "it'll remember, it's the same assistant": no. Every call, and every new session, starts from only what's explicitly put in front of it. Continuity within a session is the program resending a growing history, not the model remembering.

M2 — "there's room, so just paste it all in": no. Bigger context, used carelessly, costs more (everything resends every step) and tends to recall worse (context rot), even with room to spare. Curate first; retrieve or save instead of dumping.
