Context and memory in an agent

The two rules

Within one session: the context only grows. Every step's tool call and result get appended; nothing is removed unless something (compaction, context editing) deliberately trims it.
Between sessions: by default, nothing survives. A new session starts with a completely empty context window. Anything from before only comes back if it was saved outside the window and is retrieved into the new session.

Terms

Token
A chunk of text, roughly three-quarters of a word. Every token sent to or from the model counts against both the context window's size limit and the call's cost.
Context window
The full set of tokens the model can attend to in one call: the system prompt, the tool definitions, the conversation so far, every tool result, and what it's writing now. Finite, shared by all of those at once.
System prompt
The instructions that set up the model's role and task for this call.
Tool definitions
A short description of each tool the model may call and what it needs to call it.
Retrieval
Fetching just the relevant saved piece (a manual page, a note) into context on demand, instead of loading everything that exists.
Note-taking
The agent writing a short summary or log to a file outside the context window, to be retrieved and reread in a later session. Lightweight: no database required.
Compaction
Summarizing older turns of one long session into something shorter, to keep that session usable without overflowing the window. Within-session only — it does not save anything for next time.
Context editing
Clearing out stale tool results from one long session that are no longer needed. Also within-session only.

Which fix, when

ProblemFixCrosses a session boundary?
This session's context is about to overflowCompaction or context editingNo

Need the agent to remember something for a future sessionWrite a note, then retrieve it next timeYes — this is the whole point

Five traps

"A bigger window means I don't need memory or retrieval."
Cost still scales with every token sent, and accuracy can still drop as irrelevant text piles up.
"The model remembers me from last time."
The model holds nothing between calls; any apparent memory is the program re-inserting saved text.
"Context window and memory are the same thing."
The window is the per-call budget; memory is the external storage and retrieval system that decides what fills it.
"Writing a note is enough."
Something must still fetch the note and insert it into a later context window, or it's never seen again.
"Once the window fills, everything is remembered automatically."
Without deliberate compaction or notes, trimmed or dropped content is simply gone.
